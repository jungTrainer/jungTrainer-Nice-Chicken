# IMP-10: 성장 곡선과 정확한 금액

완료일: 2026-10-12. 기준: `origin/improvement-imp09-20261012`, `b233b92964ecc62b6bbda1e5f101fad37ea6735d`.
보관 브랜치: `improvement-imp10-20261012`. [Draft PR #4](https://github.com/jungTrainer/jungTrainer-Nice-Chicken/pull/4)는 IMP-09 브랜치 대상이다. main 병합·배포는 수행하지 않았다.

## 먼저 측정한 문제

[변경 전 JSON](verification/IMP-10-economy-before.json)에 실제 Chromium 측정을 기록했다. `2^53`원에 1원을 기록하면 보유금은 변하지 않지만 매출은 1원 증가했다. 메뉴 연구 Lv.1200 비용은 `Infinity`였다. 기존 Lv.999는 약 `9.534×10^69`원, 엔딩은 `9.99×10^70`원으로 완전 성장 화성에서도 약 `1.584×10^44`년의 예상 수익이 필요했다.

연속 운영·자동 구매·실제 연구 시간 모델은 화성까지 약 47.8시간, 엔딩은 30일 측정 범위 내 미도달이었다. 플레이 길이를 확인했고 사용자가 **수일간 누적 운영**을 선택했다. 목표와 금액 정책의 가정/근거는 [성장·금액 정책](../economy-policy.md)에 기록했다.

## 구현 방법

1. 첫 스크립트 `money.js`에 정확한 원 연산을 모았다. 안전 정수는 기존 Number, 큰 정수는 10진 문자열이고 BigInt는 연산 내부에서만 사용한다. 덧셈·지출·비교·비율·정확한 비용과 알려진 금액 필드 migration을 한 곳에서 정의했다.
2. 보유금·매출·메뉴·기여도·직원 경력과 주간 매출 차액이 같은 단위로 처리되도록 정산 경로를 교체했다. 가격 효과의 순서와 1회 적용을 유지하고 정수 비율 계산 후 원 단위에서 내림한다. 일반/직원/메뉴 연구·지점 비용·임금·쿠폰 교환도 같은 비용/비교 정책을 사용한다.
3. 기존 Number는 이미 저장된 실제 정수 값으로 변환한다. 저장 키·export envelope version은 유지하고 moneyEncoding만 추가한다. 원본 없는 과거 수익·사라진 정밀도를 추측 복원하지 않는다. 원래 지점의 확정 미수령 금액/내역을 다시 평가하지 않는다. 미션/인증서/쿠폰·엔딩의 지급/사용 플래그와 알 수 없는 확장 데이터는 유지한다.
4. 금액/encoding이 바뀐 migration만 dirty로 표시한다. 초기 boot는 기존 write 지연을 유지한다. 매출 기록은 모든 ledger 값을 계산한 뒤 대입하고, 수령의 범위/저장 실패는 원래 금액/receipt로 rollback한다. 오프라인 추정도 후보 receipt를 계산한 뒤 전체를 교체한다. 저장 감시·전역 함수 재설치 래퍼를 추가하지 않았다.
5. 지점 해금 비용·배율·서비스/연구 속도는 유지했다. 엔딩 보유금을 100해(`10^22`)로 바꾸고 레벨 2–10 초반 구간과 지점 비용에 맞춘 100/250/400/550/700/999 앵커를 설정했다. 이전 높은 레벨·엔딩 해금/보상은 낮추지 않는다. XP는 현재 레벨에서 다음 레벨까지 진행률을 표시하며 최고 레벨은 100%다.
6. 큰 금액 표시와 비용 overflow를 보완했다. 매우 큰 값은 지수 표기로 화면을 보호하고 정확한 원 값은 title/dataset/백업에 유지한다. 구매는 표시 문자열을 파싱하지 않는다. 메뉴 연구 안내의 잘못된 매회 1.5배 표현을 실제 레벨당 +50%로 고쳤다. 추가 연구는 10,000단계에서 종료하며 과거 더 높은 레벨은 보존한다.

위 결과는 자동 구매 전략과 통제한 고객 공급 모델이다. 실제 장면의 이동/인내심·이탈이나 사람이 구매하는 간격, 8시간 오프라인 한도를 포함하는 수일 실시간 플레이 완료 기록은 아니다. 모델의 평균 수익/시간 적분은 Number 근사이며 실제 원 단위 정산과 분리했다. 가정과 선행 메뉴 해금의 수익 희석 문제를 정책 문서에 명시했다.

## 남은 문제

- 98.5시간은 문서화한 전략 모델이다. 실기기·오랜 실시간/미접속 플레이 데이터로 도달 시간의 분포를 확인해야 한다. 비용/속도 변경 시 같은 모델과 정확한 정산 검사를 함께 실행한다.
- 무작위로 해금 메뉴를 선택하는 현재 주문은 높은 연구 후 저레벨 메뉴를 열면 평균 가격을 낮출 수 있다. 직원 역할·메뉴 선택의 의미와 지역별 콘텐츠는 IMP-11에서 설계한다. 특정 메뉴를 잠가 두는 전략을 숨겨 새로운 수익으로 보정하지 않는다.
- 새 문자열 금액 백업은 IMP-10 이후 앱에서 읽어야 한다. 구 앱으로 내려갈 때 자동 변환하면 1원 정밀도를 다시 잃을 수 있어 제공하지 않는다. 4,096자리/10,000단계 경계와 거부 정책은 금액 정책 문서에 명시했다.
- 여러 탭의 LocalStorage 충돌·다중 키 원자성, 구간 전체의 ES module 전환, 원본 없는 간판 asset, PWA/캐시 갱신과 서버 쿠폰 인증은 이번 범위 밖이다. PWA/운영은 IMP-12다.
- 개발 브랜치/draft PR만 변경했다. main의 과거 workflow와 Pages main 배포는 그대로이며 병합·배포/branch protection은 별도 승인 후 진행한다.
