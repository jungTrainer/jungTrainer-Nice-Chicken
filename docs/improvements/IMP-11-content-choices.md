## 분석에서 구현까지

기존 직원은 기본 속도·등급·공용 교육과 대사가 있었지만 역할을 선택할 수 없었다. 지역은 가격/비용/배경만 달라 같은 성장을 반복했고, 이야기는 엔딩에 집중됐다. 모든 해금 메뉴를 고르게 주문하는 규칙은 높은 연구 뒤 저렴한 메뉴를 해금할 때 평균 수익을 낮췄다. [구현 전 측정](verification/IMP-11-content-before.json)에서 후라이드 연구 Lv.10/지점 Lv.1은 99,000원, 양념 해금 뒤 평균 64,900원으로 34.44% 감소했다. 연구하지 않은 경우에는 평균이 증가했다.

[콘텐츠 설계](../content-design.md)에 선택의 이유·크기·단위·소유권·저장 실패 계약을 먼저 정리하고 아래를 구현했다.

- 경영 리포트의 **운영·이야기** 탭에서 균형/매장/포장 방향을 선택한다. 매장은 자동 서빙 +4%, 배달/온라인 수익 -4%; 포장은 반대다. 지역별 이름/이야기와 독립 선택을 제공하고 숨은 지역 추가 배율은 만들지 않았다.
- 고용한 직원 중 담당자 한 명을 선택한다. 남편은 직원 서빙 +4%, 아토는 배달 빈도 +4%, 첫째딸은 온라인 빈도 +4%, 둘째딸은 새 손님 인내 +1초, 사위는 배달 수익 +4%, 손자는 메뉴 수익 +2%다. 모든 직원의 기존 교육·서빙 순번·경력 수익은 계속 유지한다.
- 전체 메뉴의 동일 확률과 해금된 대표 메뉴 한 종 중 새 주문의 후보를 선택한다. 방문/배달/온라인/새 오프라인 추정이 한 원본을 사용한다. 기존 손님의 메뉴나 확정 receipt는 바꾸지 않는다. 평균 기본 가격/정산 가격/실제 능력을 같은 함수로 표시하고 지정 메뉴 미션 안내를 제공한다.
- 각 지역에 도착/직원 1명/메뉴 2종/첫 연구/지점 Lv.10/6명 고용/엔딩 완료의 7개 이야기 단계를 제공한다. 성장 조건에 따라 열리며 읽기 표시는 지점에 저장한다. 직원마다 짧은 역할 이야기도 있다. 읽기·닫기·전환은 금전/쿠폰/미션 보상을 지급하지 않는다.

새 효과는 기존 연구·이벤트·엔딩 계수에 한 번 적용한다. 자동 서빙 방향은 기존 이벤트 저항을 계산한 뒤 곱하고 인내 +1초는 기존 인내 계산 뒤 더한다. 배달 빈도는 기존 전체 빈도 계수에 적용하고 0.6초 하한은 유지한다. 보여 주는 능력과 실제 고객 공급/이벤트의 제한을 구분한다. 메뉴 가격과 정산은 IMP-10 정수 원 API를 사용한다. 과거 누락 수익은 보정하지 않았다.

## 저장·서비스·입력 보존

새 `management`는 지점별이다. 방향/담당자/메뉴/읽음과 알려지지 않은 확장 필드를 snapshot에 보존한다. 없는 필드는 균형·담당자 없음·전체 메뉴로 중립이다. 잠긴/잘못된 메뉴는 전체 운영으로 정규화하고 미고용의 유효 담당자 데이터는 휴면으로 보존한다. 직원 교육/경력은 기존 본사 원본을 유지한다.

선택·읽기는 no-op guard, 명시적 dirty와 force save, 실패 rollback을 사용한다. 실패하면 이전 선택/snapshot/시각/dirty를 복원한다. 교환·급여·쿠폰/인증서·미션/엔딩 플래그를 바꾸지 않는다. 선택 클릭은 서비스 updater를 호출하지 않는다. 배달 효과가 바뀌면 다음 실제 서비스 갱신에서 기존 서명/진행 비율 정책을 사용하고, 미완료 주문/미수령은 원래 지점에 남는다.

새 모달/loop/입력 소유자 없이 기존 리포트의 탭·포커스·Escape·inert/배경 입력 guard를 사용했다. 44px 버튼·줄바꿈·스크롤을 적용한다. 선택 후 버튼 포커스를 유지하고 읽음 버튼이 비활성화되면 탭으로 돌린다. 설치 순서/전역 목록·[데이터 범위](../data-ownership.md)·[실행 구조](../runtime-architecture.md)·[개발 명령](../development.md)을 갱신했다.

작업 전에 있었던 IMP-10 보고서의 한 줄 편집은 수정하거나 커밋하지 않았다. `/workspace/imp11-preexisting-user-edit.patch`에도 보존한다. 이 편집은 아래 패치/번들의 IMP-11 변경 범위에 포함하지 않는다.

## 남은 문제

- 모델은 실제 수일 연속/미접속 플레이가 아니다. 메뉴를 미리 해금하는 다른 전략과 대기 담당자의 효용, 실제 선택 빈도/엔딩 시간 분포는 추가 사용자 플레이로 검증해야 한다.
- 지역별 이름·이야기·저장은 구분하지만 새 수치 효과의 크기는 같다. 새로운 지역 전용 수치 규칙/대형 자산·음성/긴 분기 이야기는 추가 설계와 밸런스 측정이 필요하다.
- 새 선택 필드는 IMP-11 이후 앱에서 읽어야 지점별 기능을 유지한다. 구 앱으로 되돌려 다시 저장하는 경로는 지원하지 않는다.
- PWA/서비스워커 캐시·안전한 업데이트·오프라인 앱 실행, 원본 없는 간판 자산, 여러 탭/다중 키 저장 원자성, 서버 쿠폰 인증은 아직 남았다. 정산/모달과 별도의 IMP-12 범위다.
- 개발 브랜치/draft 리뷰만 만들고 main/Pages는 그대로다. 병합·배포·branch protection 변경은 별도 승인 후 진행한다.
