## 결과와 구현

직원 6명이 고용·관리 화면·자동 서빙·성장 효과·급여·반복 미션에 같은 기준으로 포함된다. 직원 교육과 개인 누적 수익의 기존 공용 범위를 유지하고 화면에 설명했다. 고용·매출·기여도·미수령·서비스 진행은 지점별로 저장하며 지점 이동·재접속·가져오기에서 올바른 런타임으로 복원한다.

먼저 새 Chromium 검사 3개로 관리 버튼 10개/직원 순번 5명, 다른 지점에서 지급되는 온라인 주문, 새 지점 초기화가 지우는 공용 인증서 플래그를 재현했다. 수정 후 같은 검사와 16개 추가 검사, 기존 58개를 실행했다.

1. `getStaffCount`/`getHiredStaff`를 직원 수의 공통 기준으로 삼고 고용 상한도 `STAFF_POOL.length`에 연결했다. 모든 직원 교육 버튼 12개를 표시하고 여섯 번째 직원에게 실제 자동 서빙 수익을 귀속한다. 현재 지점에서 미고용한 직원의 교육 구매는 거절한다.
2. 최대 성장 후 미션의 남은 교육 가능 횟수에 여섯 번째 직원도 포함했다. 이미 반복 서빙으로 전환된 목표나 완료 목표를 되돌리지 않고 기존 진행·지급 플래그를 유지한다.
3. 320px 화면에서 직원 터치 중심이 서로 겹치지 않도록 폭에 맞춰 간격·반경을 계산했다. 실제 여섯 번째 직원 터치가 다른 직원에게 전달되지 않는지 확인했다.
4. `branches.js`가 저장 가능한 지점별 서비스 진행과 실행 중 전역 타이머를 연결한다. 출발 지점 진행을 저장하고 도착 지점의 주문·배달·직원 순번으로 재바인딩한다. 배달 간격은 REC-03의 연구·버프 변경 시 비율 유지 규칙을 그대로 사용한다. 미완료 진행은 비활성 지점에서 정지한다.
5. 자동 서빙·손님 생성·이벤트 검사 진행과 절대 버프 시각을 지점 snapshot에 포함했다. 이동 시 시각 연출·클릭 버프는 끄되 세션 일일 사용 제한은 유지한다. 가져오기·초기화는 이전 상태의 연출을 제거한다.
6. 공용 인증서는 자동 주간 초기화로 지우지 않도록 명시적 새 주간 시작과 분리했다. 유효기간 종료와 기존 인증서 사용 후 새 주간 시작은 유지한다. 이동·새 지점 완료·재미리보기로 이미 지급한 음료 쿠폰을 추가 지급하지 않는다.
7. 알 수 없는 지역·잠긴 지역·같은 지역 선택을 처리하고 지점 이동 저장 실패 시 이전 상태로 복구한다. 저장 실패 뒤에도 본사 금액·미수령·출발 진행을 보존한다.
8. 첫 손님 생성의 700ms 지연 콜백도 시작한 상태·지점을 확인하게 했다. 옛 초기화가 다른 지점/새 상태에 고객을 생성하지 않는다.

## 데이터와 저장 호환

정식 규칙은 [본사·지점 데이터 규칙](../data-ownership.md)에 정리했다. 기존 저장 키·버전·보유금·직원 교육·개인 수익·지급 완료 미션·쿠폰·엔딩을 유지한다. 미수령 금액과 확정한 메뉴별 내역은 재계산하지 않는다. 가격·수익·연구 배율과 엔딩 목표액을 변경하지 않았다.

직원 개인 수익은 공용 누적이고 지점의 직원 기여도는 해당 지점 매출이다. 과거의 두 값이 서로 맞지 않더라도 추측 분배·합산·보정을 하지 않는다. 레거시 지점 내부 직원 데이터는 보관하되 현재 최상위 공용 값을 덮어쓰지 않는다.

새 `serviceTimers`가 없는 저장은 미완료 진행 0으로 시작한다. 기존 금액/보상이 줄거나 과거 지급이 새로 생기지 않는다. 옛 지점 데이터에서 새 필드가 빠진 경우 기본값을 보완해 이전 지점 값이 남지 않게 했다.

## 남은 문제와 IMP-08

- 전역 함수 교체·감싸기와 설치 순서, main.js의 이전 정의가 남아 있다. `branches.js`도 REC-03 캐시와 기존 엔진 전역 변수에 명시적으로 연결한다. IMP-08에서 실행 경로를 하나로 정리한다.
- 저장 snapshot 동기화 래퍼와 중요 상태 감시가 여전히 존재한다. 제거 전 명시적인 dirty/저장 경로를 만들어 동일 회귀 검사를 유지해야 한다.
- 효과 합산·반복 DOM 작업·저장 횟수와 이동 시 전체 상태 복제 비용의 측정은 IMP-08이다. 규모가 작은 현재 상태에서는 검증되었지만 지점·로그 증가 시 비용이 커질 수 있다.
- 비활성 지점의 추가 오프라인 영업 기능을 도입하지 않았다. 현재는 활성 지점만 운영하며 연구/시간형 버프는 절대 시각 정책이다.
- 과거 직원/지점 수익의 누락분은 복원할 원본이 없다. 큰 수 정밀도·성장 곡선·엔딩 목표액은 IMP-10, 여러 탭 충돌·서버 혜택 검증은 별도 운영 범위다.
