## IMP-07 범위와 완료

1. 직원 고용 최대 6명과 화면/자동 서빙 선택의 5명 제한을 일치시킨다.
2. 공용 보유금·쿠폰·엔딩과 지점별 성장·매출·미션·연구의 데이터 범위를 명시한다.
3. 직원 교육·개별 수익과 지점 기여도의 저장 규칙을 정하고 기존 값을 임의로 합산하거나 과거 수익을 생성하지 않는다.
4. 지점 이동에서 온라인·배달·자동 서빙 타이머와 미수령 보상이 다른 지점에 섞이지 않게 한다.
5. REC-01~05와 IMP-06의 저장·보상·정산·입력 규칙을 유지하며 지점 이동·재접속·백업·가져오기를 브라우저로 검증한다.
6. 새 58개 검사와 문법 검사를 유지하고 보고서·IMP-08 프롬프트를 갱신한다.

2026-10-12 완료. [데이터 규칙](data-ownership.md)과 [IMP-07 보고서](improvements/IMP-07-staff-branches.md)에 구현·호환·검증·남은 문제를 정리했다. 기존 저장의 직원 수익을 지점별 값으로 추측 분배하거나 중복 합산하지 않았다.

## IMP-08 범위와 완료

1. 클래식 전역 함수와 설치 순서를 먼저 목록화하고 저장·성장·정산·렌더링·실행 타이머의 의존성을 명시한다.
2. core 모듈이 교체한 main.js의 이전 정의를 검증하면서 제거하고 단일 실행 경로로 정리한다.
3. branch snapshot 저장 동기화, dirty 표시, 저장 감시 래퍼를 명시적 상태 변경/저장 호출로 대체한다. 래퍼부터 삭제하지 않는다.
4. 지점 서비스 타이머와 연구 간격 캐시의 소유권을 명시하여 전역 런타임 재바인딩 의존성을 줄인다.
5. 불필요한 반복 DOM·효과 합산·저장 작업을 측정하고 줄인다. 본사/지점 데이터·미수령·지급 완료 보상·엔딩·모달 입력 규칙과 정산 공식은 유지한다.
6. 현재 77개 검사, `npm run check`, `npm test`와 브라우저 저장/재접속/지점 이동 검증을 유지하고 커밋·패치·번들·IMP-09 프롬프트를 남긴다.


2026-10-12 완료. [실행 구조](runtime-architecture.md), [전체 전역 목록](runtime-globals.json), [IMP-08 보고서](improvements/IMP-08-state-modules.md)에 단일 실행 경로·상태/저장 계약·측정과 브라우저 검증을 정리했다. 정산·보상·엔딩 목표와 본사/지점 데이터 범위는 유지한다.
