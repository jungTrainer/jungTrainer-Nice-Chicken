# 본사·지점 데이터 규칙

적용일: 2026-10-13, IMP-07/IMP-08/IMP-10/IMP-11. 저장 키와 버전은 유지한다.

## 본사 공용

| 데이터 | 규칙 |
| --- | --- |
| `money` | 모든 지점이 같은 보유금을 사용한다. 지점 매출은 별도로 기록한다. |
| `profile`, `soundOn`, `play`, `lastSeenAt` | 사용자·설정·전체 플레이 시간과 앱 부재 기준 시간이다. |
| `staffStats[key].auto`, `.tip` | 직원별 교육은 전 지점에서 공유한다. 구매는 해당 직원이 현재 지점에 고용되어 있을 때만 가능하며 현재 지점 구매 미션에 기록한다. |
| `staffStats[key].earned` | 해당 직원이 전체 지점에서 새로 받은 수익의 누적이다. 현재 지점 기여도와 같은 범위로 해석하지 않는다. 기존 금액을 그대로 유지한다. |
| `coupons`, `benefitsLog` | 보유 쿠폰과 혜택 기록은 본사 공용이다. 지점 이동은 지급·소비를 하지 않는다. |
| `cert` | 현재 인증서의 발급·사용·유효기간은 본사 공용이다. 새로운 지점이나 그 지점 주간의 자동 초기화는 유효한 발급 플래그를 지우지 않는다. 재미리보기는 추가 쿠폰을 지급하지 않는다. |
| 엔딩 플래그·`robotGrandson` | 해금·완료·로봇손주 효과는 공용이다. 지점 이동은 추가 보상을 지급하지 않는다. |
| `regionUnlocked`, `branches`, 현재 지역 선택 | 해금 목록과 지점 저장을 관리한다. 지점별 사업 데이터는 `branches[id].data`에 저장한다. |

인증서의 기존 명시적인 사용 후 새 주간 시작 동작과 유효기간 종료 처리는 유지한다. 자동 주간 초기화와 명시적인 새 주간 시작을 구분한다. 미션 진행은 아래의 지점별 규칙을 따른다.

## 지점별

현재 구현은 활성 지점의 값을 최상위 `state`에 복사해 실행하고 `branches[id].data`에 snapshot으로 저장한다. 최상위에 위치했다는 이유만으로 본사 공용 데이터는 아니다.

고용 수를 포함한 `upgrades`, `delivery`, `online`, `research`, `menuLevels`, `menuStats`, 평점·레벨, 급여 기준, `missions`, `stamps`, 온라인/오프라인 매출, `contrib`, `unattributedSales`, `offlineReward`가 지점별이다.

- 가족 직원은 최대 6명이다. 고용·관리 화면·서빙 순번·효과 계산·급여·미션의 직원 범위는 같은 `STAFF_POOL`을 사용한다.
- `contrib.staff`는 현재 지점에서 직원이 새로 받은 기본 매출·팁의 합계다. 직원의 본사 누적 수익을 더하거나 과거 누락분으로 채우지 않는다.
- 미수령 보상과 메뉴별 추정 금액은 생성된 지점에 남는다. 다른 지점에서 수령하거나 성장 효과를 바꿔 재평가하지 않는다.
- 이벤트·`buffEndTime`과 서비스 진행은 해당 지점에 귀속된다. 시간형 버프·연구 완료 시각은 기존의 절대 시각을 유지한다.

## 서비스 진행과 화면 런타임

| 데이터 | 이동·재접속 정책 |
| --- | --- |
| `serviceTimers.onlineOrders` | 미완료 온라인 주문의 0~1 진행도. 지점에서 떠나면 정지하고 돌아오면 해당 지점의 진행으로 이어간다. |
| `serviceTimers.deliveryMs`, `.deliveryIntervalMs`, `.deliverySignature` | 해당 지점 배달 경과 시간·결정된 간격·효과 조건이다. 복원 후 연구·버프 상태가 바뀌면 REC-03처럼 진행 비율을 유지해 간격을 다시 계산한다. |
| `_autoServeAcc`, `_staffRot` | 자동 서빙 대기 진행과 다음 직원 순번이다. 다른 지점으로 가져가지 않는다. |
| `_spawnAcc`, `_eventCheckAcc` | 손님 생성·이벤트 검사 진행도도 해당 지점에 남긴다. |
| 고객·선택·라이더·클릭 연출 | 기존처럼 이동 시 고객/선택은 새로 시작하고 라이더·활성 클릭 버프·대사를 비운다. 같은 앱 세션의 클릭 사용 제한은 이동 중 유지한다. 가져오기·초기화는 세션 연출을 초기화한다. |
| 첫 손님 생성 지연 콜백 | 시작한 상태 객체·지점이 여전히 활성일 때만 실행한다. 다른 지점이나 초기화된 새 상태를 변경하지 않는다. |
| 게임 루프·자동 저장 주기 | 앱 전체에서 실행한다. 게임 루프가 활성 지점만 진행하며 비활성 지점에 추가 수익을 만들지 않는다. |

재접속 오프라인 정산도 마지막 활성 지점에만 기존 정책으로 수행한다. 비활성 지점에 별도 오프라인 수익을 추가하지 않는다. 정산된 미수령 금액은 서비스의 미완료 진행과 별개다.

## 호환과 실패

새 선택 필드는 `serviceTimers`이고 기존 `_staffRot`, `_eventCheckAcc`, `buffEndTime`을 지점 snapshot 범위에 포함했다. 필드가 없는 저장은 진행 0부터 시작하며 기록되지 않은 과거 주문을 만들지 않는다. 부적절한 간격·음수·비유한 진행은 정상 기본값으로 보완한다.

현재 저장의 최상위 직원 교육·수익 값을 공용 원본으로 유지한다. 오래된 지점 데이터 안에 별도 `staffStats`가 있다면 원본 필드는 저장/내보내기에 남기되 공용 값에 합산하거나 덮어쓰지 않는다. 알려지지 않은 과거 수익의 지점을 추측하지 않는다.

성공한 지점 이동은 출발 진행과 도착 상태를 함께 저장한다. 저장 실패 시 출발 지점·본사 보유금/보상·미수령·서비스 진행·클릭 효과를 복구하고 실패를 알린다. 잠긴/알 수 없는 지역은 이동하지 않으며 같은 지역 선택은 진행을 초기화하지 않는다.


## IMP-08 실행 계약

데이터 범위·저장 버전은 유지하고 소유 코드에서 `markStateChanged`와 저장 호출을 명시한다. [실행 구조](runtime-architecture.md)를 따른다. 강제 저장과 내보내기는 항상 활성 지점 snapshot과 서비스 진행을 먼저 동기화한다. 별도 snapshot/dirty 감시 래퍼는 없다.

`ServiceRuntime`은 활성 상태/지점과 배달 효과 입력 캐시를 소유한다. 지점 이동·상태 교체에서 명시적으로 bind/capture하며 저장된 JSON 서명과 결정한 배달 간격을 복원한다. 효과 공유 캐시는 동기 tick/UI 범위가 끝나면 폐기하고 저장하지 않는다. 순번·자동 진행은 서빙 직전 차감/갱신하여 정산 저장에 실제 진행을 남긴다.

가져오기·초기화 후보의 저장 실패는 원래 root 객체·진행·미수령·본사 보상과 클릭 효과를 복원하며 기존 엔딩 실행을 취소하지 않는다. 성공한 가져오기만 기존 엔딩/입력을 복원한다. 사용자가 확인한 초기화가 성공하면 새 상태를 저장하고 옛 backup을 지운다. 닫기·내보내기·실패한 초기화는 수령·보상 삭제·추가 지급을 하지 않는다.

## IMP-10 금액 형식

금액 데이터의 본사/지점 범위는 위 표와 같다. 안전 정수는 Number, 큰 정수 원은 부호 가능한 10진 문자열로 저장한다. `moneyEncoding: "won-integer-v1"`은 본사 루트 metadata다. 숫자 자체를 캐시·타이머 객체로 옮기거나 지점별 돈을 합산하지 않는다. 본사 직원 경력 수익, 각 지점 매출/기여도/메뉴 earned, 주간 매출 기준, 원래 지점의 확정 미수령 모두 알려진 필드만 변환한다. 고아 branch staffStats와 확장 필드, 지급/사용 플래그는 유지한다.

확정 미수령의 금액/메뉴 내역은 연구·가격·레벨·지점 성장 변경 뒤에도 재평가하지 않는다. 과거 Number가 잃은 원이나 기록 없는 매출을 복원하지 않는다. 새로운 구매 비용은 정확한 정수 비율 식을 사용한다. [표현/정산/저장·성장 정책](economy-policy.md)을 함께 따른다.

## IMP-11 운영·이야기

`management.focus`(방향), `leadStaff`(담당자 한 명), `menuPolicy`/`featuredMenu`(새 주문 메뉴), `readStories`(읽기 표시)는 지점별이다. 활성 view와 `_branchKeys()` snapshot에 포함하며 다른 지점에서 다른 선택을 유지한다. 공용 직원 교육/경력 데이터는 그대로 사용하고 담당자 필드로 이동하지 않는다. 미고용 담당자는 효과가 휴면이고 지점의 고용 범위만 적용한다.

기존 저장의 기본값은 균형·담당자 없음·전체 메뉴로 중립이다. 해당 지점에서 잠긴/알 수 없는 메뉴 선택은 전체 운영으로 정규화하고 알려지지 않은 확장 필드/미래 읽기 id는 유지한다. 읽기 표시는 명시적 클릭과 실제 잠금 조건으로 저장하며 보상을 지급하지 않는다. 역할/방향/메뉴 전환과 화면 닫기는 미수령·쿠폰·미션·인증서/엔딩 플래그를 수정하지 않는다.

선택/읽기/가져오기/초기화의 저장 실패는 이전 선택과 실제 서비스 소유권을 보존한다. 새로운 메뉴는 다음 주문/오프라인 추정에만 쓰고 손님이 이미 요청한 메뉴와 이전 receipt의 메뉴 내역은 보존한다. 급여·서비스 회전·연구 절대 시각과 배달 캐시 계약은 유지한다. [설계와 기준](content-design.md)을 따른다.


## IMP-12 웹앱 설치/운영

manifest·콘텐츠 버전·셸/선택 미디어 캐시는 저장 데이터 밖의 웹앱 자산이다. `PwaRuntime`의 대기 워커·적용 flag와 설치 prompt도 세션 런타임이다. 새 save version/쿠폰 metadata/서버 잔액을 만들지 않는다. 안전한 업데이트의 강제 저장은 기존 본사/지점 및 서비스 capture를 사용하고 미수령·지급/사용 이력·관리/읽음을 그대로 남긴다. 닫기·설치/업데이트 확인은 수령이 아니다.

기존 쿠폰/PIN·인증서 사용은 기기 기록이며 서버/매장 인증이 아니다. 서버 쿠폰 id·계정·매장 권한·발급/사용 ledger는 존재하지 않는다. 이를 기존 로컬 수량에서 추측 생성하지 않는다. 실제 서버 연결과 혜택 운영은 [별도 조건](coupon-server-contract.md)으로 검토한다. 워커는 API POST/인증 결과를 캐시하지 않는다.

## IMP-13 여러 창의 데이터 접근

게임 저장 하나의 작성자는 origin/기존 저장 키 기반 Web Lock을 보유한 한 문서다. 세션 id/역할/epoch/원문 기준은 저장 필드가 아니다. 새 작성자는 최신 본 저장에서 전체 본사·지점·미수령·지급 이력과 서비스 소유권을 다시 로드하며 다른 문서 view를 합산하지 않는다. 독자는 화면/최신 저장본 백업만 제공하고 dirty/게임 저장·사업 지급/이동/import/reset은 하지 않는다. 무해한 view 정규화도 저장하지 않는다.

확정 receipt를 닫기/운영 요청/인계/캐시 정리만으로 수령하거나 삭제하지 않는다. hidden/복귀의 새 추정은 기존 활성 지점·8시간 규칙을 사용하고 이전 확정 내역은 재평가하지 않는다. 성공 저장 후 인계와 종료 복구는 원 단위·공용/지점·타이머/연구 캐시 규칙을 유지한다. 다른 저장 원문을 발견한 작성자는 conflict에서 멈추고 두 백업을 구분한다. [지원·인계·복구 정책](session-ownership.md)을 따른다. 로컬 PIN/쿠폰은 서버 인증/운영 ledger로 바뀌지 않는다.
