# UX-5 지도 표시 설계

지도는 위아래 목록이다. 각 카드는 지점 이름/영업·이동·잠김 상태, 지금 할 일, 이동/오픈 버튼의 세 행으로 읽는다. 현재 지점과 선택한 지점을 구분해 강조한다. 열린 지점의 이야기 매출은 기존 `Campaign.regionSummary`와 `Campaign.sales`를 읽고, 다음 잠긴 지점은 기존 `getRegionUnlockCost`와 정확한 원 API로 비용 준비율을 표시한다. 1원 부족을 100%로 반올림하지 않는다. 오픈 자금을 모아도 이전 이야기 조건이나 현재 지점의 다음 오픈 대상 조건이 남으면 버튼을 활성화하지 않는다.

카드의 이동/오픈은 기존 `mapGo`/`mapUnlock` 클릭 처리로 이어진다. `BranchManager`의 이동·해금·차감·저장 실패 복구, `getNextRegion`과 캠페인 선행 조건은 수정하지 않는다. 카드 자체 클릭/Enter/Space는 기존 지점 선택 동작이고, 카드 안의 네이티브 버튼은 별도 입력으로 1회만 실행한다. 선택은 기존 mapSelected/dirty 규칙을 유지한다. 현재 지점을 거슬러 이동했을 때도 오픈 비용 준비는 보여주며 실제 다음 지역 오픈은 기존 위치 규칙을 따른다.

자세한 지점별 기록 매출·보관된 이야기 목표·해금 조건·가족 목표는 하단 ‘자세히’로 모은다. 요약은 지역 이야기 수와 가족 목표 한 줄이다. 확정된 받을 수익을 매출에 합산하거나 이야기를 조회만으로 해금/완료하지 않는다. 기록의 goalAtUnlock과 기존 지급 상태를 보존한다. 지도 열기·화면 갱신·상세 접기에는 상태 변경/정규화/dirty/저장이 없다.

열린 지도는 기존 UI 갱신 주기로 금액/목표를 다시 읽는다. 카드와 상세 DOM을 보존해 새 금액 표시가 스크롤·펼침·키보드 포커스를 지우지 않게 한다. 지도는 세로 스크롤, 하단 상세는 높이가 제한된 스크롤이며 닫기는 고정된 헤더에 남는다. 기존 모달 소유권·Escape·열기 버튼으로의 포커스 복귀를 사용한다. 기존 가로 배치 assertion과 접힌 문구 위치 assertion만 새 표시 구조로 갱신하고 금액·차감·선택·저장·포커스 검사는 유지한다.

자동 Chromium의 360/390px 전후 캡처·작은 가로 화면·터치/키보드·금액 경계·실제 이동/해금·저장 실패·순수 조회 검사를 PR에 연결한다. 실기기·스크린리더는 미확인이며 UX-6는 소유자 실기기 확인 후 별도 진행한다.
