# 수동 검증과 배포 점검표

갱신: 2026-10-13, IMP-16. 설치·실행·진단 명령은 [개발 안내](development.md), 보존할 규칙은 [데이터 규칙](data-ownership.md)과 [실행 계약](runtime-architecture.md)을 따른다. 자동 검사 280개는 Chromium 기준이며 아래 확인란은 수동 실행 기록을 남길 때 체크한다. 실제 사용자 저장은 먼저 백업하고 초기화/가져오기는 별도 테스트 브라우저 프로필에서 수행한다.

## 준비와 기록

- [ ] commit SHA, Node/브라우저 버전, OS·viewport, 검증 시각을 기록했다.
- [ ] `npm ci`, 고정 Chromium 설치, `npm run doctor`, `npm run check`, `npm test` 또는 공통 `npm run test:ci`가 완료됐다.
- [ ] 결과가 280개 실행·실패 0·skip 0인지 확인하고, 실패 시 `test-results`와 Actions run URL을 남겼다.
- [ ] 저장소 루트에서 `python3 -m http.server 8000 --bind 127.0.0.1`를 실행하고 HTTP와 실제 브라우저를 확인했다. 자동 검사는 자체 서버를 사용한다.

## 실행과 정산

- [ ] 이름 저장 후 스플래시가 사라지고 고객/캔버스/메뉴·하단 탭이 동작한다. 반복 page error가 없다.
- [ ] 고객 선택·맞는/틀린 서빙·팁·온라인 주문·배달이 동작한다.
- [ ] 채널별 새 수익이 보유금·매출·메뉴 통계·기여도에 한 번 기록되고, 과거 누락분이 추측 추가되지 않는다.
- [ ] 해금 메뉴/지점 성장 가격과 구매 버튼의 비용이 실제 정산/차감과 일치한다.

## 저장·보상·지점

- [ ] 강제 저장·재접속 후 현재 지점, 고용/교육/매출·미션·쿠폰·엔딩이 복원된다.
- [ ] 직원 최대 6명이 관리·터치·자동 서빙에 포함된다. 교육/개인 누적 수익은 공용, 고용/매출/기여도는 지점별이다.
- [ ] 지점 A→B→A에서 온라인 분수·배달 간격/진행·자동 진행/순번이 섞이지 않는다. 비활성 진행은 멈추고 시간형 연구/버프는 절대 시각을 따른다.
- [ ] 미수령 금액이 원래 지점에 남고, 모달 닫기만으로 수령·삭제되지 않는다. 재접속 후 한 번 수령된다.
- [ ] 백업 만들기/가져오기 후 공용/지점별 값과 legacy 필드가 보존된다. 내보내기는 수익을 지급하지 않는다.
- [ ] 합성 저장 실패에서 dirty 재시도와 지점 이동·수령·가져오기·초기화의 복구가 동작한다.
- [ ] 확인한 초기화 성공은 새 상태를 저장하고 옛 backup을 제거한다. 실패하면 기존 진행이 유지된다.

## 연구·미션·엔딩

- [ ] 연구 0/1/10레벨의 직원 처리량과 배달 간격/수익이 반영되고 재접속만으로 진행 중 간격이 재추첨되지 않는다.
- [ ] 일간/주간 8종 진행·구매 카운터·최대 성장 후 목표와 날짜/주간 전환이 동작한다.
- [ ] 지급 완료 목표·쿠폰·인증서 재미리보기에서 보상이 다시 지급되지 않는다.
- [ ] 엔딩은 플레이 중 조건에서 해금되고 버튼·재생·완료 효과가 한 번 적용된다.
- [ ] 재접속·가져오기·초기화 및 중도 닫기에서 이전 엔딩의 입력/타이머/음원이 새 상태를 변경하지 않는다.

## 화면과 입력

- [ ] 320×568, 390×844, 844×390, 1280×900에서 패널/모달/엔딩이 넘치지 않고 스크롤·닫기·하단 탭·안전 영역이 유지된다.
- [ ] 실제 터치·키보드 Tab/Enter/Space/Escape로 동작하고 닫으면 열었던 버튼에 포커스가 돌아간다.
- [ ] 최상위 모달 밖의 메뉴·canvas·숨겨진 패널 입력이 막힌다. PIN 확인/취소와 창 크기/키보드 변경이 동작한다.
- [ ] 실기기 터치·스크린리더·스피커 청취는 별도 기록했다. Chromium 자동 통과만으로 완료 표시하지 않는다.

## CI와 승인 후 배포

- [ ] 현재 SHA의 Game CI 결과를 확인했다. 취소·skip을 전체 검사 통과로 기록하지 않았다.
- [ ] PR이 열린 브랜치 push는 select가 중복 checks를 건너뛰고, 해당 PR의 검사는 실행됐다.
- [ ] main 병합·배포를 위한 별도 승인이 있다. 개발 브랜치 CI 성공만으로 배포를 시작하지 않는다.
- [ ] 승인 뒤 실제 Pages 배포 SHA·빌드 결과·HTTPS·asset 경로·새 저장/기존 저장·재접속을 확인했다.
- [ ] Pages는 현재 main 루트 legacy 설정이다. PWA 버전/대기/실패 복구와 여러 창·미수령 중 적용은 현재 규칙으로 검증한다.

## 손상·명시적 복구·다중 창

- [ ] 신규(본/backup/fence 없음)와 둘 다 손상/읽기 거절을 구분했다. 손상 자료가 기본 상태로 덮어써지지 않았다.
- [ ] 정상 primary만 자동 운영하고 유효 backup은 미리보기다. source/시각/지점/미수령/오류를 보고 원문 내보내기·취소·선택을 실제 입력으로 확인했다.
- [ ] archive write/primary write 실패에 원본·정상 backup·확정 receipt를 유지했고 재시도에 한 번 commit했다. 백업 쓰기 실패와 본 쓰기 실패 안내를 구분했다.
- [ ] 초기화 준비/본 저장/삭제 실패를 구분하고 이전 세대 backup을 자동 복원하지 않았다. 권한 복구/외부 변경만으로 운영이 재개되지 않았다.
- [ ] 정상 writer·reader·복구 중 lock 보유자의 tick/수령/이동/import/reset/PWA/인계 규칙을 검증했다. 새 writer는 최신 성공 저장에서 시작했다.
- [ ] 실제 SW 오프라인 셸에서 손상 자료를 검사/선택/재접속했고 설치 standalone·대기/실패 업데이트에서 원문/보상을 보존했다.
- [ ] Firefox/WebKit의 실제 실행 범위/버전·잠금/저장/복구·인계를 기록했다. 클라우드 실행 제한 밖 검사와 실제 iPhone/Android 설치·OS 종료 검증을 구분했다.
- [ ] 320×568/568×320에서 진단 scroll/원문/가져오기/닫기와 복구 후 미수령·지점 조작을 확인했다.


## 반복 미션·방문용 쿠폰

- [ ] 기존 v1 기간의 진행/완료/paid·확정 미수령·쿠폰을 유지하고 다음 일간/주간에 각각 v2가 적용된다.
- [ ] 최대 성장/대표 메뉴/엔딩 뒤에도 v2 목표가 가능하며 잠긴 메뉴/구매/사용 불가 채널이 필수가 아니다. 접속 시간은 writer tick만 센다.
- [ ] 성장 업적 보기와 정확 서빙 5회 도전 재시작/재열기는 실물 쿠폰을 추가 발급하지 않는다. 자동 서빙도 인정하며 타이머/직원 순번을 바꾸지 않는다.
- [ ] 테이블/새 식사 방문·직원 보여주기/닫기·제공 확인/PIN·primary 성공 기록을 구분하고 취소/저장 실패에는 차감/사용 상태를 복원한다.
- [ ] 같은 기기 현재 방문의 음료 재사용을 막고 다른 기기 합계는 직원 확인이 필요하다고 안내한다. 기록 정리/지점/게임 도전으로 제공 플래그가 풀리지 않는다.
- [ ] 기존80개 로그의 보존 규칙과 신규 전후 잔량/방문 id를 확인한다. 옛 로그의 전후 수량을 추측 만들지 않는다.
- [ ] 양배추/무 제공량·새 발급 한도는 검토안과 실제 기본값을 구분하고 기존5,000만원 교환/지점별 일간·주간 발급을 확인한다.
- [ ] 320×568/568×320 실제 입력/스크롤/포커스·오프라인 SW·설치/다중 창·인계/복구·export/import/reset에서 방문/paid/미수령을 보존했다.

## 지역 엔딩·이지/노말

- [ ] 구 저장이 기존 운영100해로 열리고 native 확인 취소/저장 실패 때 모드·paid·미수령·dirty가 그대로다. 성공 선택 뒤 표시와 실제 미래 지점 비용이 일치한다.
- [ ] 정확한 지역 매출1원 경계에서 이야기만 해금되고 미수령/다른 지점 수익을 더하지 않는다. 다음 지점은 이전 지역 이야기와 실제 비용이 필요하다.
- [ ] 보기/닫기/Escape는 완료·칭호·돈/쿠폰을 변경하지 않는다. 첫 완료의 성공 저장만 기념을 기록하며 실패→재시도/다시보기는 추가 효과가 없다.
- [ ] 모드/지점/기간 전환·재접속·백업/가져오기에서 archive/가족once·방문 기록을 보존한다. 실패 복구·다중창 인계는 최신 성공본만 상속한다. reset은 명시적으로 초기화하고 옛 세대가 돌아오지 않는다.
- [ ] 열린 지역 이야기에서는 가족 자동 팝업/PWA 적용/인계가 끼어들지 않는다. 작은 세로320×568/가로568×320에서 완료/닫기/스크롤/포커스와 배경 터치 차단을 실제 입력으로 확인한다.
- [ ] 실제 SW 오프라인·실패/대기 update와 설치standalone reader를 확인했다. 수익 배율·5,000만원 교환·실물 운영 한도를 변경하지 않았다.
- [ ] 설계 목표와 모델90/312분을 실제 사람 보장 시간으로 표기하지 않았고 모바일 OS/접근성·실제 누적 사람 플레이는 별도 기록했다.
