# IMP-11 콘텐츠·운영 선택 설계

2026-10-13. 기준 IMP-10 `68437f1`. 데이터/금액은 [소유권](data-ownership.md), [원 정책](economy-policy.md)을 따른다.

## 관찰과 선택 이유

기존 콘텐츠는 직원 6명의 대사·등급·기본 속도, 2종 공용 교육, 6개 지역의 가격/비용/배경, 9개 메뉴 해금/연구와 엔딩이다. 직원마다 이미 속도/팁 기여가 다르지만 플레이어가 역할을 선택하는 경로는 없다. 지역은 같은 업그레이드를 반복하며 이야기의 연결은 주로 엔딩에 몰려 있다.

방문·배달·온라인은 모든 해금 메뉴를 동일 확률로 고르고 오프라인은 같은 메뉴들에 수량을 나눈다. 후라이드 연구 Lv.10/지점 Lv.1에서 기본 가격은 99,000원이다. 양념을 해금하면 30,800원이 섞여 평균 64,900원으로 **34.44% 감소**한다. 연구 Lv.0에서는 평균이 16,500→23,650원으로 증가한다. 해금이 항상 손해도 항상 이득도 아니다. [구현 전 측정](improvements/verification/IMP-11-content-before.json)은 0/1/10 연구와 1/2/3/9종을 비교한다.

자동으로 모든 가격을 올리거나 과거 매출을 보정하면 실제 기록과 저장 계약을 바꾼다. 대신 플레이어가 앞으로의 주문 메뉴를 선택한다. 전체 운영은 이전과 같은 동일 확률이고 대표 메뉴는 해금한 한 메뉴다. 연구한 후라이드를 유지하거나 다른 메뉴로 전환할 수 있다. 평균 기본 가격과 각 정산 가격을 실제 공통 함수로 보여 준다. 메뉴 지정 미션이 필요하면 전체/해당 메뉴로 바꾸도록 안내한다. 기존 손님의 주문과 확정 미수령은 변경하지 않는다.

사용자가 선택한 수일 누적 운영을 유지하기 위해 운영 방향과 직원 담당자의 새 효과는 2~4%로 작게 설정했다. 정산·처리량을 유리하게 바꾸는 선택과 매장/포장의 절충을 제공하고 무료 전환으로 실험할 수 있게 한다. 비용·보유금·미션 구매 횟수는 전환에서 바뀌지 않는다. 새 수익만 영향을 받는다.

## 선택과 실제 효과

기본값은 **균형 운영·담당자 없음·전체 메뉴**다. 모든 효과가 중립이며 기존 120개 fixture를 바꾸지 않는다.

| 선택 | 적용 |
| --- | --- |
| 균형 운영 | 기존 효과/속도 유지 |
| 매장 중심 | 최종 자동 서빙 성장 계수 ×1.04, 배달·온라인 수익 계수 ×0.96 |
| 포장 중심 | 자동 서빙 계수 ×0.96, 배달·온라인 수익 계수 ×1.04 |
| 남편: 서빙 조율 | 직원 속도 계수 ×1.04; 기본 자동 운영은 유지 |
| 아토: 배달 길잡이 | 배달 빈도 계수 ×1.04; 기존 0.6초 하한과 추첨/진행 비율 정책 유지 |
| 첫째딸: 온라인 창구 | 온라인 빈도 계수 ×1.04 |
| 둘째딸: 대기 안내 | 새 손님의 최종 인내 시간 +1초; 기존 손님의 남은 시간은 바꾸지 않음 |
| 둘째사위: 포장 품질 | 배달 수익 계수 ×1.04 |
| 손자: 메뉴 기록 | 최종 메뉴 수익 계수 ×1.02; 로봇손주 효과도 기존 1회 효과에 포함한 뒤 적용 |

지역마다 매장/포장 선택의 이름과 이야기가 다르다(부산의 해변 식탁/숙소 주문, 서울의 퇴근길/사무실, 일본의 거리/역, 미국의 이웃/도심, 화성의 공동 식탁/탐사팀). 효과는 같은 크기로 유지해 이미 큰 지역 가격 배율에 숨은 추가 배율을 얹지 않는다. 담당자는 해당 지점에서 고용한 한 명만 선택한다. 나머지 직원의 기존 교육·서빙·회전·기여도는 계속 적용된다. 다른 지점에서는 다른 담당자를 선택할 수 있다.

연구/이벤트/엔딩은 기존 합산 순서 그대로다. 새 선택은 그 결과의 계수에 한 번 곱한다. 배달 빈도는 기존 deliveryMul의 빈도 기여도 포함한 전체 계수에 적용한다. 효과 합산과 실제 `computeRates`, 정산은 같은 값을 사용한다. 매장/포장 자동 서빙 계수는 기존 이벤트 저항/상한을 계산한 뒤 적용하여 물류 이벤트 중에도 선택의 4%를 보존한다. UI는 능력/방문/온라인 처리량을 표시하며 고객 공급·이벤트와 배달 최소 간격 때문에 실제 처리 수가 제한될 수 있음을 알린다. 선택으로 서비스 진행을 차감·생성하거나 즉시 수익을 지급하지 않는다. 간격 효과 변경은 다음 실제 서비스 갱신에서 기존 비율을 보존한다.

## 이야기와 보상

지역별 도착/가족 첫 고용/메뉴 2종/연구 첫 완료/지역 Lv.10/6명 고용/엔딩 완료의 7개 장면을 제공한다. 지역별 도착·성장 문장과 직원 역할의 짧은 이야기가 수일 성장 사이에 놓인다. 엔딩은 기존 이야기와 입력/1회 효과 그대로 유지한다. 해당 장면은 실제 성장 조건으로 열리며 읽기 표시만 지점에 저장한다. 잠금 장면은 제목과 조건만 표시한다.

읽기·재열기·닫기·선택은 돈/쿠폰/인증서·미션 지급을 하지 않는다. 새 스토리 보상 시스템을 만들지 않았다. 일간/주간 보상은 원래 시스템만 지급한다. 이 정책은 여러 번 클릭하거나 저장 실패 후 다시 읽어도 경제 효과를 늘리지 않는다.

## 저장·입력 계약

`management = {focus, leadStaff, menuPolicy, featuredMenu, readStories}`는 **지점별**이며 활성 view와 snapshot 모두에 포함한다. 없는 필드는 중립 기본값으로 보완한다. 알려진 잘못된 선택/잠긴 메뉴는 중립으로 정규화하고 모르는 확장 필드는 유지한다. 고용되지 않은 유효 담당자 데이터는 보존하되 효과는 휴면이다. 직원 교육/경력은 기존 공용 원본을 사용하고 이 객체에 옮기거나 합산하지 않는다.

선택과 읽기는 명시적 dirty → 기존 force save다. 이미 같은 선택/읽기라면 추가 write가 없다. 실패하면 이전 management/최종 접속 시각/dirty와 활성 snapshot을 복구하고 UI를 되돌린다. import/reset의 기존 원본 root/서비스/엔딩 rollback을 유지한다. 금액 저장 encoding/키·확정 미수령·지급 완료/쿠폰 flags는 바꾸지 않는다.

새 UI는 기존 경영 리포트의 **운영·이야기** 탭이다. 새로운 모달/타이머/입력 소유자를 만들지 않는다. 버튼은 44px 이상, 자동 줄바꿈·세로 스크롤을 사용하고 기존 Escape/포커스/배경 입력 guard를 따른다. 선택 후 포커스를 유지하고 읽음 버튼이 비활성화되면 탭으로 포커스를 돌린다. 보고서 표시에서 자동 읽음이나 보상 수령을 하지 않는다.

평균 가격·선택 효과와 이전 IMP-10의 같은 자동 구매/연구 모델을 비교한다. policy만 다르고 후보·연구 시간·급여·지점 재시작·30일 horizon은 같다. 담당자는 고용 후에만 효과를 받는다. planning 적분은 Number 근사, 실제 정산은 정수 원 검사로 확인한다. 모델의 고객 이동/인내심 제외·메뉴 해금 lookahead 부재 등 기존 한계를 유지한다. 따라서 대기 안내의 보호 효과나 사람이 선행 메뉴를 해금하는 전략을 수익 증가로 추측해서 모델에 넣지 않는다. 결과/실제 서비스와 한계는 완료 보고서에 남긴다.
