# 미션·실물 쿠폰 확정 정책

IMP-18, 매장 운영자 승인(2026-10-15). 종전 IMP-15 미적용 발급 검토안을 대체한다. 서버·계정 없이 기기 내부 기록과 직원 확인을 사용한다. 조정 가능한 수치는 `js/core/config.js`의 `COUPON_POLICY` 한 곳에 둔다.

## 발급과 사용

| 경로 | 새 정책 |
| --- | --- |
| 웰컴 | 본/백업/초기화 표시가 모두 없는 신규 저장만 첫 이름 입력·안내 완료 버튼으로 음료 1장. 빈 이름도 가능. 닫기·재열기·기존 저장·게임 초기화는 지급 아님 |
| 사용 잠금·유효기간 | 웰컴은 다음 한국 날짜 00:00부터 사용. 새 음료는 발급 시각부터 30×24시간, 새 무/양배추는 14×24시간. expiresAt 시각부터 만료 |
| 일간 올클 | 음료 스탬프 +1, 모든 지점 합쳐 기기 하루 1회. 무/양배추 직접 지급 중단 |
| 주간 올클·인증서 | 스탬프 +2와 무/양배추 1장, 모든 지점 합쳐 한국 달력 주 1회. 올클 저장 시 지급하며 인증서 발급·재열기는 다시 지급하지 않음 |
| 게임머니 구매 | 스탬프 +2, 기기 한국 달력 주 1회. 가격은 max(50,000,000원, 현재 자동 추정 분당 수익×120분). 새 직접 음료 교환 중단 |
| 매장 방문 | 새 테이블 방문을 직원 공개 PIN으로 확인·저장할 때 스탬프 +5, 모든 지점 합쳐 기기 하루 1회. 게임 방문 도전과 별개 |
| 카드 | 30개로 음료 1장. 스탬프 발급은 한국 달력 월 1장. 웰컴은 별도로 1회 지급하며 월 한도를 사용하거나 예약하지 않음. 남은 스탬프 이월, 최대 30개 |
| 월 한도 도달 | 카드가 찬 상태로 그 달 발급을 마쳤으면 다음 달 1일 00:00 이후 첫 실행/활성 운영에서 한 번 지급. 실패 시 지급·카드 차감을 복원하고 저장 재시도 가능 |
| 음료 사용 | 같은 테이블 한 방문에 한 병 + 같은 기기 한국 날짜 하루 한 장. 새 쿠폰은 사용 가능·미만료인 것 중 만료가 가까운 순, 그 뒤 무기한 기존 쿠폰 사용 |

한국 날짜는 기기 표시 시간대와 무관하게 UTC+9, 주는 월요일 00:00부터 다음 월요일 전, 월은 1일 00:00부터 다음 달 전이다. 날짜별/주별 지급 기록은 지점 이동·미션 재시작·로그 정리로 지우지 않는다. 시계 조작·LocalStorage 편집 방지나 다른 기기 횟수 공유·서버 인증은 없다. 실제 테이블 제공을 직원이 확인해야 한다. 무/양배추는 기존 통합 쿠폰이며 제공량·추가 제공 횟수를 새로 제한하지 않는다.

## 기간 이행·기존 보상

저장 v10 이하를 v11로 옮기며 `coupons.drink/veg`는 무기한 기존 수량으로 그대로 둔다. 새 날짜형 쿠폰은 별도 HQ `couponLedger.lots`에 id/type/source/issuedAt/usableAt/expiresAt/usedAt을 보관한다. 기존 수량을 날짜형으로 변환하거나 과거 발급·사용·수익을 추측해 채우지 않는다.

기존 목록/진행/paid/인증서와 지점별 현재 기간은 보존한다. 첫 이행 때 일간 기준은 다음 한국 날짜 00:00, 주간/교환 기준은 현재 활성 지점의 진행 중 주간 종료 시각(이미 지났으면 현재)으로 저장한다. 각 지점의 새 기간 시작에 `dailyRewardPolicy/weeklyRewardPolicy=2`를 남기며 이미 시작한 보상 v1 기간은 완료까지 기존 보상을 유지한다. 기존 주간이 더 오래 남은 다른 지점도 해당 기간을 소급 취소하지 않는다. 신규 저장은 처음부터 새 정책이다. 반복 목표 목록의 v1/v2 표식과 보상 정책 표식은 별개다.

반복 v2 주간의 “일간 올클”은 새로 시작하는 주간 목록부터 5회다(`CONFIG.weeklyRepeatDailyClears`). 진행 중인 v1 및 이전 v2의 7회 목표·진행·완료·paid는 바꾸지 않는다. 집계 상한·미션 카드·안내·스탬프 칸은 현재 저장된 목표를 따른다. 다른 지점도 각 지점의 다음 주간부터 적용한다. 웰컴 월 한도 분리는 `welcomeCountsTowardMonthlyLimit: false`로 적용하며 이미 저장된 월 발급 기록을 추측 차감하거나 보상을 재지급하지 않는다.

기존 기간의 일간은 veg 1장·주간 미션용 스탬프, 인증서 발급은 기존 drink 1장이다. 이행 전 주간 교환도 기존 5,000만원당 음료 1장을 유지한다. 이 수량들은 확정 기간 보상이며 새 월 발급 원장에 추측 포함하지 않는다. 음료 하루 사용 제한은 출시 후 실제로 새 기록을 남긴 사용부터 적용하며 과거 로그를 보고 오늘 사용을 추측하지 않는다.

## 분당 수익·정확한 가격

활성 지점의 해금·운영 메뉴 평균 원 가격에 자동 서빙 처리량(min(방문 주문/분, 실제 2배 자동 처리량/분))과 직원 팁 기대값을 적용하고, 온라인 주문 및 배달 연구·라이더·현재 버프 채널 추정액을 더한다. 배달은 실제 간격 함수의 평균 흔들림과 12% 휴식 기대값을 사용하며 견적이 난수를 소비하거나 서비스 진행/연구 캐시를 바꾸지 않는다. 수동 서빙·주문 대기·랜덤 팁·오프라인 확정 미수령은 실측 분당 수익으로 합산하지 않는다. 이는 현재 자동 운영의 추정 모델이며 실제 수익 보장이 아니다.

원 평균/채널 추정은 정확한 원 API로 하향 절사한다. 동일 `quote()`의 원 가격을 표시·잔액 검사·차감에 사용한다. 화면 표시 후 가격이 달라졌으면 구매하지 않고 새 가격을 표시한다. 표현 한계에서는 구매를 막는다. 지점/모드/연구를 바꿔도 이미 확정된 미수령 가격은 재계산하지 않는다.

## 저장·가져오기·복구

발급·사용·구매·직원 방문은 primary commit 성공 뒤 확정된다. 실패하면 해당 쿠폰/스탬프/기간 기록·인증서·방문·로그·가격 차감을 복원하고 다른 게임의 미저장 진행과 dirty를 유지한다. 독자 창과 오래된 PIN 콜백은 지급하지 않는다. 조회·닫기·인증서 재열기·로그 정리는 보상 경로가 아니다.

일반 백업 import는 게임 진행을 교체하되 **이 기기의 현재 새 원장 전체를 유지**한다. 가져온 스탬프·날짜형 쿠폰·월 발급/일 사용 기록을 합치거나 과거 상태로 되돌리지 않는다. 출시 후 직원 방문/사용 기록이 있으면 현재 방문과 혜택 로그도 유지해 이전 테이블의 제공 확인을 되감지 않는다. 새 보상 방식의 인증서도 현재 기록을 유지한다. 다른 기기의 신규 혜택을 이전하는 기능이 아니다. 기존 무기한 수량의 명시적 snapshot 가져오기는 원래 규칙을 유지한다. 게임 초기화도 새 원장/한도를 보존하고 웰컴 자격을 새로 만들지 않는다. 기존 게임·무기한 쿠폰 초기화의 명시적 동작은 그대로다.

IMP-14의 검사/정규화/원문 archive/초기화 세대/실제 commit 구분을 유지한다. 명시적 복구에서도 알고 있는 현재 새 원장을 우선 보존하며 후보끼리 합산하지 않는다. 최신 원장이 손상·삭제되고 오래된 백업만 남았다면 그 뒤의 실제 사용은 알 수 없다. 명시적 snapshot 복구의 이 한계는 서버 없이 완전히 해결할 수 없고 수량/과거 사용을 추측 보정하지 않는다.

## 게임 목표와 범위

일간/주간 8종의 반복 v2, 지점별 방문 게임 도전(정확 서빙 5회), 성장 업적은 유지한다. 게임 도전 재시작·지역 엔딩·모드 변경은 실물 혜택을 추가 지급하지 않는다. 공용/지점 데이터·타이머/연구 캐시·원 단위 정산·엔딩 1회·입력 소유권·PWA 대기/실패 규칙을 유지한다. 백엔드·계정·서버 쿠폰·광고·헬은 개발 범위 밖이다.
