# 저장 복구·원본 보존 정책

IMP-14 설계, 기준 IMP-13 c7402dd. 초기 Chromium 측정은 [측정 JSON](improvements/verification/IMP-14-recovery-before.json)에 보관한다. 본 저장 손상+본 write 실패에서 정상 backup이 손상 원문으로 바뀌었고, 둘 다 손상된 경우 기본 상태가 본 저장에 쓰였으며, reset의 backup 삭제 실패 후 손상에서는 옛 500원 미수령/쿠폰이 복원됐다.

정상 본 저장과 신규(본/backup/초기화 표시 모두 없음)는 기존 동기 정산/저장을 유지한다. 손상·읽기 거절·지원하지 않는 형식에는 운영/dirty/자동 저장/PWA 적용/인계를 멈추고 후보를 표시한다. JSON 검사와 알려진 필수 구조/금액·보호 상태 검사, 정규화, 실제 commit은 별개다. 유효 backup은 미리보기이며 사용자의 명시적 선택 전 수익/보상을 지급하거나 본 저장을 교체하지 않는다.

원문 archive는 명시적 복구 전에 별도 키에 보관하며 실패하면 복구를 진행하지 않는다. 원문 export는 parse/정규화하지 않은 본/backup/세대 표시를 포함한다. 정상 저장은 검사한 정상 본 저장만 backup으로 회전한다. 손상 원문은 정상 backup을 덮어쓰지 않는다. backup write 실패는 기존 정상 본 저장의 새 write를 막지 않으나 실패를 표시한다. 본 write 실패는 dirty/메모리 진행을 보존한다.

전체 IndexedDB 이관은 하지 않는다. 기존 본/backup 키와 루트 게임 구조·수동 envelope v1을 유지한다. 새 root _saveRecovery는 version/generation/commit만 기록한다. 별도 resetFence는 새 generation과 이전 원문 식별자를 primary commit 앞에 준비한다. 준비 write 실패이면 reset하지 않는다. 유효 primary가 새 세대이면 reset 이후이고, 이전 원문과 같으면 준비 뒤 primary 실패/중단이다. primary가 손상되어 결과를 확인할 수 없으면 이전 세대 backup을 복구 후보로 허용하지 않는다. 후속 정상 write는 준비된 세대로 진행을 보존하여 전진한다. reset primary 성공 뒤 backup 삭제가 거절되어도 옛 세대는 자동 복원되지 않는다.

원문 식별자는 길이와 두 32-bit 해시로 실수/경합 감지에 사용하며 암호학적 무결성·인증은 아니다. LocalStorage 다중 키는 원자적 transaction이 아니므로 중간 상태를 분류하고 불확실한 복구는 중단한다. 준비/원문 보관 완료와 실제 primary 성공을 구분한다. 표시/새 구조는 구 셸이 이해하지 않으므로 구 창을 닫고 새 버전에서 사용한다. IMP-13의 원문 비교/협력 잠금을 유지한다.

복구 선택은 원본 snapshot의 명시적 교체다. 오래된 backup의 최신성/paid 이력을 추측하지 않고 합산하지 않는다. 확정 미수령은 해당 후보의 금액/내역을 그대로 유지한다. 복구 commit은 접속 기준을 현재로 옮겨 불확실한 과거 구간의 새 오프라인 수익을 만들지 않는다. 새 연구 완료/정상 달력 전환은 복구 후 기존 규칙을 따른다. 이미 지급된 상태를 확인할 자료가 사라진 경우 복원 보장 밖이며, 원본과 수동 백업을 보존해 선택의 한계를 표시한다.

archive는 진단 원문이며 자동 로드 후보가 아니다. reset 뒤 이 원문을 명시적으로 export/import하는 사용자 작업은 자동 부활과 구분한다. 읽기 거절/디스크 장애/전체 사이트 삭제에서 데이터를 만들어내지 않는다. 본/backup 유효성·초기화 세대가 모호하면 운영을 차단하고 권한 재확인/원문 백업/외부 백업 가져오기를 제공한다. Web Locks 없는 문서는 진단/백업만 제공한다.

## 형식과 제한

현재 루트의 필수 금액·레벨·성장/연구/메뉴 객체와 보호 상태는 타입을 검사한다. 버전 없는 구 최소 저장은 정상 profile/coupons/확정 receipt 구조로 게임 저장임을 식별한 경우에만 누락 연구/메뉴 통계를 기존 migration으로 보완한다. 새/알 수 없는 버전·encoding·잘못된 paid 플래그는 coercion하지 않는다. 입력은 8MiB 이하이며 원문 export는 문자열 그대로 보존한다. archive write가 quota에 막히면 자동 원본 삭제 없이 복구를 거부하고 수동 내보내기를 제공한다.

backup이 정상이고 primary만 깨졌어도 최신 paid/미저장 진행을 확인할 수 없다는 한계를 안내하고 명시적 snapshot 교체만 수행한다. 이것은 과거 수익/쿠폰을 합산하는 복원 알고리즘이 아니다. 초기화 세대 표시는 지원 앱의 자동 복구를 제한하며 사용자 직접 LocalStorage 편집/구 앱/명시적 외부 import를 서버 권한처럼 막지 않는다. 앱/SW는 백엔드 요청·실혜택 사용을 하지 않는다.
