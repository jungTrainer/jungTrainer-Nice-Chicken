# 매장 방문·반복 플레이·엔딩·광고 방향 제안

2026-10-13. IMP-13 이후 사용자 의견을 반영한 기획안이다. 게임 코드·저장·실제 서비스 운영은 변경하지 않았다. 아래 시간·배율은 설계 목표/검토안이며 검증된 현재 성능이나 확정 밸런스가 아니다.

## 확정된 방향

- 백엔드·계정·서버 쿠폰 검증 개발을 향후 계획에서 제외한다.
- 게임과 음료 1병·양배추·무 서비스 쿠폰은 오프라인 사용을 중심으로 한다.
- 음료는 **한 테이블의 한 방문/식사에 한 번** 제공한다. 테이블 번호가 다음 손님에게 재사용되는 경우는 별도 방문으로 구분하는 운영안을 제안한다.
- 성장 완료/엔딩 이후에도 고객이 반복 플레이하고 방문 때 혜택을 사용할 수 있게 한다.
- 엔딩 도달 시간을 재설계하고 광고는 단계적으로 검토한다.

## 권장 제품 형태

매장에서 3~5분 짧게 즐기는 반복 플레이, 집에서 이어가는 지점 성장, 수집하는 지역 엔딩을 한 앱에 둔다. 이지/노말/헬은 별도 배포본 세 개 대신 앱 안의 모드로 제안한다. 같은 앱에서 업데이트·저장·광고 운영을 유지하면서 성장 속도와 도전 목표를 구분할 수 있다.

## 매장 혜택 운영

쿠폰 발급과 실제 사용을 분리한다. 미션 완료로 쿠폰을 얻고, 방문 시 직원에게 보여 준 뒤 제공 시점에 사용 완료를 기록한다. 쿠폰 화면은 서비스 종류·사용 전/후·사용 시각·방문/테이블을 쉽게 구분하도록 한다. 음료는 고객 여러 명이 쿠폰을 갖고 있어도 같은 테이블 방문에 합계 한 병이다.

앱은 각 휴대폰의 기록이므로 여러 고객 기기 사이의 사용 횟수를 공유하지 않는다. 테이블당 한 번은 직원의 제공 확인과 함께 관리한다. 공개 로컬 PIN은 실수 방지 확인이며 서버 인증으로 표현하지 않는다. 양배추·무의 1회 양과 추가 제공 횟수는 매장 운영 기준으로 별도로 정하며, 음료와 같다고 임의 확정하지 않는다.

현재 게임머니 5,000만원당 음료 한 장 교환은 후반 성장/이지 수익 가속과 결합하면 서비스 발급이 너무 쉬워진다. 권장안은 **새 실물 쿠폰의 발급을 방문용 미션/기간별 정량 기준으로 옮기고**, 게임 성장 재화·난이도·광고 보상과 분리하는 것이다. 기존 쿠폰 수량과 사용 이력은 보존한다. 새 발급 한도/조건은 구현 전 정하고 이미 확정한 보상을 소급 취소하지 않는다.

## 미션 재설계

현재 repairMissionGoals는 구매 여지가 없으면 구매·간판·확장 목표를 반복 서빙으로 바꾼다. 이후에도 진행할 수 있는 기반은 있으나 여러 미션이 같은 행위로 바뀐다. 다음 세 종류를 분리한다.

| 종류 | 목표 예시 | 보상 방향 |
| --- | --- | --- |
| 성장 업적 | 첫 고용·연구·간판·확장·지점 해금 | 한 번의 게임 성장 보상/이야기 |
| 짧은 방문 미션 | 정확 서빙 5회·현재 해금 메뉴 2종 판매·손님 요청 해결 | 정해진 서비스 쿠폰 발급 기회 |
| 일간/주간 반복 | 서빙 수·실제 가능한 메뉴 판매·주문 처리·수일 누적 달성 | 기간별 정량 혜택과 게임 보상 |

최대 성장에도 가능한 목표만 반복 목록에 넣는다. 잠긴 메뉴·구매 불가능 항목·운영 방향 때문에 처리하지 못하는 채널을 필수 목표로 뽑지 않는다. 매출 목표는 난이도/지점 성장에 맞춰 정하고, 모든 미션을 같은 서빙 수로 대체하지 않는다.

매장 대기 시간 안에 끝낼 수 있는 작은 미션을 먼저 제공하고, 주간 목표를 매일 8종 완전 완료의 연속 달성에만 묶지 않는 안을 권장한다. 현재 기간의 완료/지급 이력과 쿠폰은 보존하고, 신규 목표는 다음 기간부터 적용하거나 명시적 호환 정책으로 옮긴다. 엔딩 이후에도 반복 미션은 계속 열린다.

## 지역 엔딩과 난이도

현재 100해 보유금 엔딩은 연속 운영 모델 약 98.5시간이다. 실제 짧은 접속/오프라인은 8시간 한도와 채널 차이가 있어 더 오래 걸릴 수 있다. 본 문서에서 불가능하다고 재측정한 것은 아니며, 매장 방문용 경험에 맞게 목표를 낮추고 달성 구간을 나누자는 제안이다.

각 지역에서 고용·지역 운영·적정 매출 등 달성 가능한 조건을 채우면 짧은 지역 엔딩을 보고, 다음 지점을 계속하거나 현재 지점에 남아 반복 운영한다. 기존 가족 최종 엔딩은 지역 이야기 끝의 최종 장면으로 연결한다. 영상을 봤다는 이유만으로 수익을 반복 지급하지 않고 해금·재생·보상 이력을 분리한다. 지역 엔딩 보상은 우선 게임 내 기념/장식/칭호로 설계한다.

| 모드 | 첫 지역 엔딩 목표 | 전체 이야기 목표(누적 능동 플레이) | 경험 |
| --- | --- | --- | --- |
| 이지 | 약 5~10분 | 약 1~2시간 | 매장 방문 중에도 달성감, 빠른 해금·가벼운 투자 |
| 노말 | 약 15~25분 | 약 5~8시간 | 여러 차례 접속하며 직원/메뉴/운영 선택 |
| 헬 | 약 30~60분 | 약 15~25시간 | 선택/투자 효율을 요구하는 선택적 도전 |

수치는 희망 목표이며 오프라인·자동 운영 포함 달력 시간과 구분한다. 능동 플레이/자동 서비스/오프라인 위주 접속을 각각 측정해서 실현 가능한 목표로 확정한다. 헬은 먼저 두 기본 모드를 검증한 뒤 추가한다. 모든 모드가 최종 엔딩에 도달할 수 있어야 한다.

수익만 몇 배 곱하면 비용·해금·미션·쿠폰 발급이 함께 무너지므로 수익, 구매/연구 비용, 지점 해금 조건, 엔딩 목표를 묶어 비교한다. 난이도별 미래 수익/비용은 정확한 원 API로 계산하고 확정 미수령은 재평가하지 않는다. 헬의 차별화는 도전과 칭호/추가 대사로 두고 실물 서비스를 더 많이 주는 구조는 피한다.

새 플레이 시작 시 모드 선택을 제안한다. 기존 플레이어에게는 원래 진행/해금/paid 이력을 유지하는 이행 정책을 마련한다. 모드 재시작이나 지역 엔딩 재생으로 실물 쿠폰·이전 보상을 다시 만들지 않는다. 기존 최종 엔딩의 1회 효과도 별도로 보존한다.

## 광고의 단계적 도입

게임/서비스 쿠폰은 오프라인에서도 동작하고 광고는 인터넷이 있을 때만 노출한다. 광고 로드 실패·차단·미지원에도 미션/쿠폰/엔딩의 정상 진행을 유지한다.

1. 매장 고객이 미션/엔딩을 즐기는 흐름을 먼저 개선한다.
2. 플레이·수령·직원 확인 버튼을 가리지 않는 고정 영역의 적은 배너부터 시험한다. 실제 노출 수·불편·재방문과 혜택 원가를 함께 평가한다.
3. 플랫폼이 지원하면 선택형 보상 광고를 검토한다. 보상은 게임 내 단기 효과/장식 등에 한정하며 음료 추가 발급·테이블 제한 해제로 연결하지 않는다. 광고 없이도 모든 모드의 엔딩에 도달하도록 한다.
4. 전면 광고는 흐름이 안정된 뒤 지역 전환처럼 자연스러운 구간에서 빈도를 제한하여 별도로 검토한다. 매장 서비스 확인 도중에는 넣지 않는다.

현재 PWA는 웹 광고 플랫폼의 지원/승인 조건을 확인해야 한다. 네이티브 앱 패키징을 선택하면 모바일 광고 SDK를 별도 검토한다. 광고 계정·플랫폼이 정해지기 전에 동작/수익을 확약하지 않는다. 사용량이 정해지지 않았으므로 예상 매출은 노출·실제 단가를 측정한 뒤 계산한다.

## 실행 순서 제안

1. IMP-14: 저장/복구를 먼저 완성한다.
2. IMP-15(제안): 최대 성장 이후 반복 미션과 방문용 쿠폰 화면/테이블 운영 규칙을 구현한다.
3. IMP-16(제안): 성장 모델을 재측정하고 지역 엔딩·이지/노말을 구현한다. 헬은 기본 두 모드 결과 뒤 도입한다.
4. IMP-17(제안): 위 실제 흐름의 사용성/접근성·기기 호환을 검증한다. 필요 모듈 분리는 기능 변경 단위로 진행한다.
5. IMP-18(제안): 온라인 광고 플랫폼을 선택해 배너부터 검증한다. 광고 callback·저장/인계·PWA·긴 운영을 함께 확인한다.
6. IMP-19(제안): 기존 저장과 오프라인을 포함한 출시/rollback 후보를 준비한다. main 병합·배포와 실제 운영 변경은 별도 승인으로 진행한다.

각 단계는 현재 197개와 추가 회귀 검사·doctor/check/test·CI, 실제 입력·실패/재시도·백업/가져오기·지점/다중 창·기존 지급 상태 보존을 유지한다. 이 순서는 기획 제안이며 이번 작업에서는 구현이나 배포를 수행하지 않았다.
