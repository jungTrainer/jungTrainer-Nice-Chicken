# UX-2 쿠폰 표시 설계

헤더와 하단의 쿠폰함은 같은 `couponContents`를 연다. 설정에서는 같은 DOM을 기존 모달로 옮긴다. 쿠폰 사용·방문·인증서 버튼과 캔버스는 하나씩만 존재하며 기존 이벤트, PIN·모달 소유권과 포커스 복귀를 사용한다. 인증서는 쿠폰함의 내부 섹션이다. 지난 기록은 기본 접힘이며, 직원 확인을 열면 사용 전후 기록도 펼쳐 확인한다. 긴 쿠폰함을 열자마자 아래 항목에 초점을 옮겨도 앱 전체가 스크롤되지 않도록 이 패널은 슬라이드 없이 즉시 연다.

표시 순서는 음료 스탬프 30칸/월 상태 → 사용 가능·잠금 쿠폰 → 적립 방법 → 주간 인증서 → 직원 확인 → 접힌 지난 기록이다. 카드 정렬은 원장의 복사 배열에만 적용한다. 기존 무기한 수량과 날짜형 쿠폰을 함께 보여주며, 헤더 수량은 기존 `available` 조회로 잠금/만료/사용 완료를 제외한다. 당일 음료 사용 제한과 방문당 제한은 기존 직원 확인 경로에서 검사한다.

쿠폰 조회에서는 정규화·보상 정산·저장을 호출하지 않는다. 본 저장·백업·게임 상태·dirty와 발급/사용/paid/교환 규칙을 바꾸지 않는다. `saveVersion`은 11 그대로다. 적립 안내는 기존 `BenefitService.commit`의 **본 저장 성공 뒤** 표시 전용 후크에서만 발생한다. 실패·읽기 전용 동기화·import·복구·재접속의 수량 차이로 적립을 추측하지 않는다. 카드 교환 후에는 실제 남은 스탬프를 표시한다.

웰컴 축하는 성공한 새 웰컴 쿠폰 결과만 알린다. 사용 가능 알림은 미사용·미만료 웰컴 쿠폰의 기존 한국 시간 사용 가능일을 읽는다. 엔딩·입력·받을 수익·복구 창과 운영권 준비 중에는 안내를 기다렸다 표시하며 보상 함수를 호출하지 않는다.

알림 확인 여부는 게임 저장과 별개의 `niceChicken_couponPresentation_v1` 키에 `welcome:<쿠폰 id>` / `usable:<쿠폰 id>`만 보관한다. 발급 권리나 수량을 담지 않으며 게임 백업/export/import/복구 대상에 넣지 않는다. 새 저장 필드·마이그레이션 없이 같은 기기/origin에서 재접속 알림을 줄이기 위한 표시 설정이다. 다른 탭의 변경은 storage 이벤트로 반영한다. 읽기/쓰기 거절 시 게임 저장 성공과 분리해 현재 문서의 메모리에서 1회를 유지한다. 이 설정 삭제·저장소 거절·다른 기기에서는 안내가 다시 보일 수 있으며, 쿠폰은 추가 지급되지 않는다.

자동 Chromium 검사는 기존 동작을 유지하면서 조회 전후 원문/dirty 불변, 360/390px 터치·키보드·Escape·포커스 복귀, 웰컴 자정/재접속, 성공/실패 적립, 다른 창 동기화와 작은 가로 화면을 확인한다. 실기기·스크린리더와 사람 사용성은 별도 확인 항목이다. UX-3는 소유자 실기기 확인 후 별도 PR로 진행한다.
