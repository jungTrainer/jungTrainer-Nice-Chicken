# UX-4 진행감 표시 설계

일반 업그레이드와 직원 교육은 기존 `upgradeCost`/`staffUpgradeCost`의 정확한 원 비용과 `moneyCompare`로 구매 가능 표시를 계산한다. 보유금 비율은 `moneyRatio`를 사용하고 백분율은 내림 표시해 1원 부족을 100%로 반올림하지 않는다. 최대 단계는 진행 막대와 구매 가능 수에서 제외한다. 목록 순서를 유지하며 상단 개수에는 화면의 시설·고용·직원 교육 구매를 함께 센다. 구매 함수·비용·정산은 변경하지 않는다.

미션은 기존 current/target/done을 조회해 진행 막대를 표시한다. done이 이미 있으면 과거 카운터를 추정 보정하지 않고 완료 표시를 유지한다. 기존 DOM/저장 목록의 순서는 보존하고 CSS로 진행 중 → 완료 순서만 보여준다. 완료 전환 때 세부 내용이 접히며 완료 상태는 항상 보인다. 사용자가 다시 펼친 항목은 매 tick마다 접지 않는다. 미션 패널의 Tab/Shift+Tab은 시각적 진행 중/완료 순서와 일치시키고 기존 모달 소유권·Escape·포커스 복귀를 사용한다. 오늘 완료한 미션 수는 기존 done 플래그를 읽어 표시하고 성장 업적은 기본 접힘이다.

`updateProgressUI`는 표시 전용이며 게임 저장 필드·키·타이머를 추가하지 않는다. 연구의 기존 startAt/endAt을 읽어 슬롯별 시간과 비율을 표시하고 남은 초는 올림한다. 시간이 지나도 화면 조회만으로 연구를 완료하지 않고 ‘완료 확인 중’을 보여준다. 기존 `updateResearch`의 완료/효과/dirty/저장은 유지하고 이전 단일 시간/막대 DOM 쓰기만 이 표시 함수로 옮긴다. 연구 요약과 목록은 같은 스크롤 안에 두어 작은 화면에서도 닫기에 접근할 수 있다. 슬롯 확장이나 성장 규칙은 추가하지 않는다.

조회·접기·정렬·진행률 갱신은 게임 상태·본 저장·백업·dirty·paid·쿠폰·인증서·지급/사용 이력을 변경하지 않는다. 새 표시/정확한 원/재접속 검사와 기존 동작 검사, 360/390px 전후 캡처와 최종 CI·Pages 확인은 단계 PR에 기록한다. 실기기·스크린리더는 미확인이며 UX-5 지도는 소유자 실기기 확인 후 별도 진행한다.
