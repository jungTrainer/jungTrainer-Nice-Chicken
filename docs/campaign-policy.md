# 지역 이야기를 잇는 모드 정책 (IMP-16)

기준 IMP-15 491e4aa. 서버/계정/광고/헬/실제 매장 운영 변경 없이 개발 브랜치에서 구현/검증한다. 기존 쿠폰/paid/5,000만원 교환과 정확한 원 정산을 유지한다.

## 측정과 설계

기존 자동 구매/연구의 30일 분 단위 모델은 부산95분·가족 엔딩5911분(98.5시간)을 재현했다. 능동 모델은 자동이 남긴 주문을 사람이 완벽히 채운다고 가정하며, 방문/이탈/장면·구매 lookahead를 제외한다. 같은 탐욕적 구매 정책이 다른 순서를 택해 능동 플레이가 항상 더 빠른 최적 전략이라고 주장하지 않는다. 오프라인은8시간마다 돌아와 기존 효과로 확정 수익을 수령한 뒤 구매/완료 연구/다음 연구를 수행하며 부재 중 새 구매/연구 시작을 하지 않는다. 30일 미도달은 검열 구간이지 무한 도달 시간의 증명이 아니다.

설계 목표는 누적 능동 플레이로 이지 첫5~10분·전체60~120분, 노말 첫15~25분·전체300~480분이다. 실제 사람의 소요 시간 보장이 아니다. 앱의 가격/속도/연구/일반 구매식을 쓰고 **지점 해금 비용·지역 매출 목표·가족 엔딩 목표**만 모드에서 바꾼다. 소득 배율을 새로 중복 적용하지 않는다. 처음에는15분 만에 전체가 끝나는/마지막만7시간 기다리는 초안도 측정했으며 그 숫자를 최종 성능으로 쓰지 않는다.

지역6개에 기록된 지점 누적 온라인+오프라인 매출 목표를 나누어 각 지역에서 성장하고 이야기를 만나도록 한다. 이미 확정한 미수령은 수령하기 전 매출이 아니며 모드/가격 변경으로 재평가하지 않는다. 과거 기록 없는 매출/부재 시간은 새로 만들지 않는다. 지역 이야기 해금은 다음 지점의 신규 오픈 조건(기존 오픈한 지점은 그대로 유지)이다. 마지막 목표에는6지역 이야기 해금과 공용 보유금이 필요하며 기존 가족 엔딩 플래그는 계속 유효하다.

## 저장·이행

모드가 없는 저장은 **기존 운영**(100해·기존 지점 비용)이다. 신규 실행도 기본은 기존 운영이며 설정의 명시적 선택으로 이지/노말을 시작한다. 유저의 이름/초기 프로필 입력을 새 자동 모달로 가리지 않는다. 선택은 native 확인→새 정책/기록 후보→force save 성공 뒤 적용이다. 실패는 기존 모드/진행/dirty와 저장 원문을 유지한다.

모드 전환은 진행을 재시작하지 않고 알려진 기존 지점 매출/해금/교육/paid·서비스 타이머와 가족 엔딩 효과를 그대로 사용한다. 낮아진 목표에 이미 충분한 기록된 매출이 있으면 이야기 해금이 가능하지만 새 돈/실물 쿠폰은 없다. 이미 해금/완료한 이야기는 모드 전환으로 잠그거나 다시 지급하지 않는다. 모드가 달라도 기념 완료는 지역당1번이다.

루트 `campaign={version:1,mode,selectedAt,regions}`는 HQ의 선택/6지역 이야기 수집이며 지점별 매출을 공용으로 합산하지 않는다. 각 record의 `unlockedAt/seenAt/badgeAwarded`는 해금·완료·기념 칭호를 분리한다. 미리보기/재생·닫기는 완료/수령이 아니다. 완료 버튼의 성공 저장에서만 기념 칭호를 한번 기록한다. 새 경제 효과/현금/실물 쿠폰 보상은 없다. unknown extension은 유지하고 알 수 없는 버전/모드/잘못된 완료 기록은 복구 후보 검사에서 중단한다. 새 모드 백업은 IMP-16 이후 셸에서 사용한다; 구 셸의 새 정책 처리를 보장하지 않는다.

## 입력·운영 경계

지역 엔딩은 공통 dim/modal·스크롤/닫기/포커스/배경 입력 owner 아래에 둔다. 재생 token은 root/region/epoch를 확인하고 늦은 완료가 다른 지점/가져온 상태/새 writer에 적용되지 않는다. PWA/인계는 열린 지역 이야기 표면에서 거절되며 닫기만 하면 원문/미수령/paid를 바꾸지 않는다. 성공 import/reset에서 재생 view를 닫고 실패는 기존 view/진행을 유지한다. 새로운 loop/타이머/연구 캐시/전역 저장 래퍼를 만들지 않는다.

게임 재화/모드가 실물 혜택 발급 기준이 되지 않는다. 지역 기념은 실물 미발급이다. 다만 기존5,000만원 교환은 유지하므로 지점의 빠른 이동으로 후반 교환이 빨라지는 위험은 남는다. 새 방문 발급/통합 한도·양배추/무 양·추가 횟수는 IMP-15 미적용 검토안으로 남긴다. 음료는 테이블 방문당 한 병이며 다른 기기 합계는 직원 확인이 필요하고 공개 PIN은 서버 인증이 아니다. 배포/매장 운영 전 검토가 필요하다.

같은 모델의 구매/연구 완료 판단은 앱 함수와 정확한 비용 값을 사용하나 시간 적분/평균율·planning 잔액은 Number 근사다. 이를 원 단위 정산 결과나 보장된 플레이 시간으로 인용하지 않는다. 실제 앱 원 경계는 별도의 브라우저 검사로 확인한다. 최대 화성의 실제0.1초 step 10분 샘플은 서빙703/배달1000/온라인2, 매출11438834002598400000000원으로 모든 모드에서 동일했다. 이는 수익 배율을 바꾸지 않았다는 고정 조건 확인이며 첫 실행부터 사람의90/312분 완주 재현이 아니다.

최초 목표 탐색에서 전체15분/마지막 지역만 수시간인 초안을 버리고, 기존 미션/쿠폰과 정산식을 바꾸지 않는 정책을 택했다. 실제 사용자의 구매 빈도·손님 실패·읽기/미션/오프라인 일정·지역 경영/메뉴 선택에 따라 시간이 달라진다. 목표는 엔딩을 불가능하게 느끼던100해 경로보다 짧은 선택을 제공하는 기준이다. 실제 사람 측정과 난이도 안내 개선은 IMP-17에서 이어간다. 이지·노말 교차 선택을 금지하지 않으며 기록된 엔딩 해금은 상위 모드에서 취소하지 않는다; 경쟁 점수/서버 난이도 인증으로 표현하지 않는다.
