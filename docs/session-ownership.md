# 여러 창의 작성자·인계·복구 정책

IMP-13, 2026-10-13. 기준 IMP-12 `6d878ef`. [소유권](data-ownership.md), [저장 계약](runtime-architecture.md), [PWA 정책](pwa-operations.md)을 따른다.

## 재현과 선택

실제 Chromium 두 창에서 각각 17원/23원 기록 후 10,040원 대신 10,023원을 저장했다. 같은 확정 500원 수령이 두 창에서 모두 성공했다고 반환했고 오래된 창을 닫으면 돈 10,000원/미수령 500원으로 돌아왔다. 부산 이동 뒤 다른 창의 저장은 창녕으로 되돌렸고 다른 창의 reset도 최신 수익을 지웠다. [측정 JSON](improvements/verification/IMP-13-concurrency-before.json)에 실제 결과를 보관한다. PWA의 업데이트 창 수 검사는 사업 작성자를 제한하지 않는다.

Chrome 151의 localhost/HTTPS는 Web Locks·BroadcastChannel을 지원한다. Web Locks는 origin 단위 배타 잠금이며 창 종료/프로세스 강제 종료에서 브라우저가 해제한다. 같은 저장 키를 쓰는 Pages 경로/설치 창도 같은 이름의 lock을 사용한다. 현재 지원을 capability로 검사하며 모든 브라우저 버전/OS에서 제공한다고 가정하지 않는다.

LocalStorage는 비교와 write의 원자적 CAS를 제공하지 않는다. 시간 lease/BroadcastChannel만으로 background 정지/동시 진입에 안전한 작성자를 보장하지 못한다. Web Locks가 없거나 API가 거절하면 **읽기 전용**으로 열고 최신 저장본의 수동 백업을 제공한다. 이번 단계는 비동기 DB로 저장 전체를 이관하지 않는다.

## 작성자와 독자

첫 잠금 획득 창만 load/정규화/오프라인 확정·tick·사업 입력·자동/종료 저장을 실행한다. 독자는 최신 저장을 표시하지만 tick·수령·구매/연구·지점 이동·import/reset·엔딩 효과·쿠폰 변경/저장을 하지 않는다. 독자 백업은 현재 저장본의 원본 envelope이며 오래된 view를 snapshot으로 쓰지 않는다. session id/epoch/lock은 저장 JSON 밖이다.

독자가 운영을 요청하면 브라우저의 lock 대기열에 들어가고 현재 작성자는 저장 후 인계를 선택한다. 엔딩/PIN/다른 모달·패널/입력/백업 작업이 남으면 인계하지 않는다. 저장 실패에는 lock/dirty/이 창 진행을 유지한다. 성공 뒤 기존 창을 독자로 만들고 lock을 해제한다. 새 작성자는 **그 시점의 최신 저장을 다시 load**하고 지점/서비스 원본을 bind한다. 이전 독자의 snapshot을 merge하지 않는다. 인계 자체는 수령이 아니다.

숨긴 작성자는 lock을 유지하고 tick을 중단하며 기존 visibility 저장을 사용한다. 복귀 시 기존 8시간 한도 오프라인 규칙으로 숨김 구간을 한 번 처리한다. 다른 창이 강제로 lock을 steal하지 않는다. 창 종료/강제 종료 후 요청한 독자는 lock을 획득하고 최신 성공 저장에서 복구한다. 갑작스러운 종료 직전의 미저장 진행은 추측 복원하지 않는다.

주요 사업 진입점/입력/타이머와 저장을 명시적으로 차단한다. PIN 같은 await는 root/지점/epoch token을 확인하여 취소·상태 교체 뒤 늦게 지급하지 않는다. 전달한 이전 창의 pagehide/beforeunload/지연 손님/타이머가 저장하거나 진행시키지 않는다.

## 충돌과 실패

작성자는 성공한 본 저장 원문을 기준으로 보관한다. 본 저장 직전에 기존 원문이 달라졌으면 저장을 거부하고 운영을 정지한다. storage 이벤트도 다른 작성의 변화를 알린다. 이 창의 미저장 백업과 최신 저장본 백업을 구분하여 제공하며 사용자가 최신본으로 다시 시작하기 전 자동 병합/덮어쓰기를 하지 않는다. 메인 write 실패에는 dirty를 유지하고 재시도/백업이 가능하다.

이 잠금에 참여하지 않는 구 버전/직접 LocalStorage 편집/확장 프로그램을 원자적으로 막는 서버 권한은 없다. 업그레이드 전에 구 게임 창을 닫는다. 예상하지 못한 구 창의 쓰기는 원문 비교/이벤트로 중단하며, 악의적인 동시 편집의 완전한 원자성을 주장하지 않는다. 공개 PIN은 로컬 기록이고 서버 인증이 아니다.

## 구 셸 정리

사용자 요청에서만 실행한다. 현재 워커가 필수 셸을 갖고, installing/waiting 후보가 없으며, scope의 모든 살아 있는 문서가 버전 질문에 응답할 때만 정리한다. 현재 워커/문서가 사용하는 버전은 보존한다. 응답 없는 구 문서·중간 설치·문서 목록 변화에는 삭제를 거부한다. 같은 scope의 명확한 셸 prefix만 처리하고 옛 v1/다른 앱/LocalStorage·backup은 지우지 않는다. 읽기 전용 창은 업데이트 적용/정리를 수행하지 않는다. PWA 적용은 기존 단독 창/저장/입력 조건도 유지한다.

## IMP-16 새 사업 입력

모드 선택·지역 해금/완료·지점 신규 오픈은 기존 canMutate와 성공 저장 계약을 사용한다. 독자는 archive를 볼 수 있으나 모드/완료/tick/dirty를 변경하지 않는다. 열린 지역 dim의 인계는 거절하며 닫기/완료 이후 최신 성공 저장만 다음 writer가 상속한다. 완료 token은 root/region/epoch를 확인한다. 지원 범위/종료/저장 실패/Web Locks 미지원 readonly 정책은 그대로다.
