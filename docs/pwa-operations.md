# PWA 설치·버전·복구 정책

IMP-12, 2026-10-13. 기준 IMP-11 `c427ecf`. 정적 Pages와 로컬 저장을 유지한다. [저장 계약](runtime-architecture.md), [소유권](data-ownership.md), [쿠폰 서버 조건](coupon-server-contract.md)을 따른다.

## 구현 전 확인

HTML은 manifest 링크와 서비스워커 등록을 비활성화했다. manifest 파일과 192/512 PNG는 존재한다. 남은 `nice-chicken-v1` 워커는 HTML·manifest·아이콘만 precache하고 JS/CSS는 네트워크에 의존한다. 캐시 이름이 고정되어 업데이트를 구분하지 못하고 activate에서 같은 origin의 다른 캐시도 지운다. 선택 자산을 addAll에 추가하면 하나의 404가 설치 전체를 실패시킬 수 있다.

앱은 클래식 스크립트 18개, CSS 1개, 엔딩 이미지 5개/음원 1개를 사용한다. 간판 PNG/JPG 원본은 없고 기존 캔버스 fallback이 있다. Google Fonts는 외부 선택 자산이다. 게임 실행·정산에 백엔드 요청이 없으며 쿠폰/PIN도 로컬이다.

GitHub Pages API 확인: legacy, main, `/`, HTTPS, `https://jungtrainer.github.io/jungTrainer-Nice-Chicken/`. 상태는 `errored`였다. 개발 브랜치 CI 성공은 배포 성공이 아니다. main 병합·배포·Pages 설정/혜택 운영 데이터 변경은 별도 승인 대상이다.

## 설치와 앱 셸

HTTPS 또는 localhost 보안 컨텍스트에서만 워커를 등록한다. manifest의 start_url/scope는 상대 경로로 Pages 하위 디렉터리에서도 동작한다. id는 기존처럼 생략하여 계산된 start_url을 설치 식별자로 사용한다(상대 id는 origin 기준이어서 다른 Pages 앱과 충돌할 수 있다). Chromium의 실제 설치 prompt가 제공될 때만 설치 버튼을 켠다. 이미 설치했거나 prompt가 없는 플랫폼에는 브라우저 메뉴/홈 화면 안내를 제공한다. headless Chromium 검증과 실제 OS의 설치 UI는 구분한다.

`npm run pwa:build`는 런타임 파일과 HTML의 정규화한 원본에서 콘텐츠 버전을 생성한다. HTML의 JS/CSS에는 SHA-256 SRI를 붙이고 워커에 완성 HTML·전체 JS/CSS·manifest·아이콘의 경로/해시를 내장한다. `npm run check`는 생성물이 원본과 일치하는지도 검사한다. 앱 변경 뒤 생성물을 같이 커밋한다. 문서/검사 변경만으로 릴리스 버전은 바뀌지 않는다.

설치 중 필수 파일을 cache:no-store로 받아 상태/MIME/해시를 검증한 뒤 저장한다. 누락·내용 불일치·quota는 새 설치를 거부하고 현재 워커/캐시를 유지한다. 엔딩 미디어는 선택 해시 목록으로 따로 검증하며 404/네트워크 실패가 셸 설치를 취소하지 않는다. 없는 간판과 외부 폰트는 캐시하지 않고 기존 그리기/기본 폰트를 사용한다.

제어된 앱의 navigation과 알려진 필수 파일은 해당 워커의 셸 캐시에서만 반환한다. 캐시가 사라지면 다른 버전의 네트워크 JS를 대신 실행하지 않고 503으로 실패한다. 최초 제어 전 네트워크 HTML의 SRI도 혼합 코드 실행을 차단한다. 잘못된 업로드/설치 실패에서는 기존 앱을 계속 쓰거나 파일 묶음을 복구한 뒤 재검사한다. 최초 설치가 완료되기 전에는 오프라인 실행을 보장하지 않는다. 웹 저장소는 origin에 귀속되므로 테스트 origin/Pages 주소 변경은 다른 저장 공간이다.

## 대기 업데이트와 안전한 적용

새 워커는 자동 skipWaiting/reload를 하지 않는다. 설정의 버전/오프라인 상태·업데이트 확인·적용 버튼을 사용한다. 첫 설치는 현재 페이지 버전과 일치하고 앱 창이 하나일 때만 제어권을 얻으며 재로딩하지 않는다. 새 버전은 사용자 클릭으로만 적용한다.

적용은 엔딩 재생/종료·엔딩 안내·PIN·프로필·미수령 등 다른 표면이 닫혀 있고 설정만 열려 있을 때 허용한다. 확정 미수령 자체는 적용을 막지 않으며 **창 닫기는 수령이 아니다**. 백업 입력이 남아 있으면 내보내기/가져오기를 마친 뒤 입력을 비워야 한다. 같은 scope의 다른 앱 탭/설치 창이 있으면 닫도록 안내한다. 워커가 창 수와 버전을 다시 확인하며 강제 저장 성공 뒤에만 활성화 메시지를 보낸다. 저장 실패에는 재로딩/보상 변경이 없다.

적용 중 입력은 기존 설정 표면 안에서 막고, 서비스 실행은 짧게 중단한다. controllerchange 뒤 한 번만 다시 열어 새 셸을 읽는다. 예기치 않은 제어권 변경은 자동 reload하지 않고 저장/버전 확인 후 명시적으로 다시 열도록 안내한다. 닫힌 앱에 대기 워커가 자연 활성화되는 브라우저 기본 동작은 다음 접속에서 새 셸을 사용한다.

## 실패 복구·캐시 범위

워커는 현재 scope를 포함한 전용 prefix로 캐시를 소유한다. 기존 `nice-chicken-v1`, 다른 앱 캐시, LocalStorage/백업/쿠폰을 삭제하지 않는다. 구 셸은 살아 있는 구 문서의 혼합을 막기 위해 자동 삭제하지 않는다. 캐시 quota가 부족하면 업데이트를 거부한다. 모든 앱 창을 닫고 개발자 도구에서 **이 앱의 구 셸 캐시만** 정리한 뒤 온라인 재접속/업데이트 확인을 수행한다. 사이트 데이터 전체 삭제는 저장/보상을 지우므로 복구 방법으로 안내하지 않는다.

기존 v1 워커가 오래된 HTML만 반환하여 새 설정이 아예 보이지 않는 배포는 개발자 도구에서 해당 scope 워커만 unregister하고 온라인 재접속한다. LocalStorage는 유지한다. 수동 저장 백업을 먼저 권장한다. 새 캐시가 손상된 경우 같은 조작으로 정상 파일을 재설치한다. 운영 배포는 전체 파일 묶음/생성 검사 통과 후 진행하고, rolling upload 동안의 해시 실패를 성공으로 숨기지 않는다.

여러 탭의 LocalStorage 동시 운영은 기존 제한이다. 업데이트 창 수 검사가 사업 데이터 동시 쓰기의 전체 lock을 제공하는 것은 아니다. 브라우저 저장소 eviction, 디스크 장애와 OS 설치 UI는 웹앱이 보장할 수 없다. 실제 혜택/서버 연결은 별도 조건을 따른다.
